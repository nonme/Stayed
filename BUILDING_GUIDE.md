# BUILDING_GUIDE.md — Архитектурное руководство для Hearthbound

> Гайд для проектирования зданий в воксельном стиле Hytale.
> Разделы: принципы → стили рас → как генерировать планы → готовые шаблоны.

---

## 1. Базовые принципы (что делает здание красивым)

### 1.1 Сначала план, потом стены

Никогда не начинай со стен. Сначала реши:
- Какая **форма фундамента** (footprint)?
- Сколько **комнат** и как они связаны?
- Где **дверь**, где **окна**?

Форма фундамента определяет силуэт здания — не наоборот.

**Рабочие формы фундамента:**

| Форма | Размер | Характер | Когда использовать |
|---|---|---|---|
| Квадрат | 7×7 — 9×9 | Уютный, простой | Жилой дом одного жителя |
| Прямоугольник | 7×10 — 9×14 | Более просторный | Мастерская, склад |
| Г-образный | ~10×12 | Интересный, ощущение роста | Крупный жилой дом |
| Крест / плюс | ~11×11 | Официальный, важный | Town Hall, храм |
| Асимметричный | любой | Живой, "достроенный" | Уникальные здания |

**Правило:** Жилые дома — малые (7×7 — 10×10). Рабочие здания — шире но не выше. Town Hall — в 1.5–2× крупнее среднего дома, не больше.

---

### 1.2 Глубина стен

Плоские стены = плохо. Каждая стена должна иметь хотя бы 1–2 блока вариации в глубину:

- **Колонны**: ставь колонны каждые 4–6 блоков, между ними — стена углублена на 1 блок
- **Эркеры**: окно выступает на 1 блок вперёд — создаёт тень и объём
- **Выступающий фундамент**: основание здания выступает на 1 блок наружу — "заземляет" строение
- **Нависающий карниз крыши**: крыша всегда выступает на 1–2 блока дальше стены
- **Правило 4 блоков**: не ставь один и тот же блок больше 4 подряд без прерывания (окном, колонной, или изменением материала)

---

### 1.3 Правило палитры блоков

Выбирай полную палитру ДО начала строительства. 3 уровня:

| Уровень | Доля | Роль |
|---|---|---|
| **Основной** | 60–70% | Определяет стиль (стена, настил) |
| **Каркас/рамка** | 20–30% | Контрастный материал (балки, обрамление) |
| **Акцент** | 5–10% | Детали, выветривание, орнамент |

**Максимум 3–5 блоков в палитре.** Больше — хаос. Меньше — скука.

**Цветовое правило:** сочетай тёплый и холодный тон. Серый камень + тёплое дерево — универсальная пара.

---

### 1.4 Крыша

Крыша определяет личность здания больше, чем стены.

- **Двускатная (gable)**: две наклонные плоскости, встречаются на гребне — средневековье, деревня
- **Плоская с парапетом**: башни, форпосты, укрепления
- **Многоуровневая**: центральный конёк + окружающие более низкие секции — для крупных зданий
- **Правило**: крыша всегда из другого материала, чем стены. Карниз нависает на 1–2 блока.

---

### 1.5 Асимметрия создаёт характер

Симметричные здания выглядят казёнными, не жилыми. Добавляй:
- Смещённый вход (не по центру)
- Разное количество окон слева и справа
- Дымоход, пристройку или навес только с одной стороны
- Небольшое "крыло" — как будто достроенное позже

---

### 1.6 Детали "обжитости"

| Где | Что добавить |
|---|---|
| Нижние углы стен | `Rock_Stone_Cobble_Mossy` — мох (влага) |
| Перед входом | Бочки, ящики, поленница |
| Рядом с домом | Небольшой огород / забор |
| Внутри | Источник света + кровать + сундук + стол |
| У фермы | Огородные грядки, чучело |

**Главное**: интерьер должен соответствовать профессии жителя.

## 2. Стили рас — детальные руководства

### 2.1 Люди — Средневековый полутимберный стиль

**Прообраз**: Английские дома с полудеревянным каркасом — белая штукатурка между тёмными деревянными балками.

**Характер**: Тёплый, обжитой, слегка потрёпанный. Эти люди здесь давно.

**Палитра блоков:**
| Роль | Блок |
|---|---|
| Стена (основная) | `Rock_Chalk_Brick` — белый/светло-серый (имитация штукатурки) |
| Балочный каркас | `Wood_Darkwood_Beam` или `Wood_Hardwood_Beam` — тёмные линии |
| Фундамент | `Rock_Stone_Cobble` — темнее, "заземляет" |
| Крыша | `Wood_Softwood_Roof_Steep` или `Wood_Darkwood_Roof_Steep` |
| Выветривание | `Rock_Stone_Cobble_Mossy` — нижние углы и фундамент |
| Мебель | `Furniture_Village_*` |

**Техника строительства:**
1. Фундамент из `Rock_Stone_Cobble` — 1–2 блока высотой, выступает на 1 блок
2. Угловые колонны из тёмного дерева (`Wood_Darkwood_Beam`)
3. Горизонтальные балки на уровне перекрытия каждого этажа
4. Заполнение стен между балками — `Rock_Chalk_Brick`
5. Каждый верхний этаж нависает над нижним на 1 блок (эффект консоли — jetty)
6. Окна: углублены на 1 блок, тёмная балка-перемычка сверху
7. Крыша нависает на 1–2 блока, под карнизом — перевёрнутые ступеньки как отделка

**Отличие домов между собой:**
- Форма фундамента: Г-образный, прямоугольник, с пристройкой-навесом
- Позиция дымохода: левый / правый / центральный
- Окна: 1 большое или 2 маленьких
- У одного — огороженный огород, у другого — открытое крыльцо

---

### 2.2 Kweebec — Органический / Природный стиль

**Прообраз**: Норы хоббитов, японские лесные святилища, домики-грибы. Построено *вместе* с природой.

**Характер**: Кривой, низкий, уютный. Ощущение выросшего, а не построенного.

**Палитра блоков:**
| Роль | Блок |
|---|---|
| Основная структура | `Wood_Birch_Trunk`, `Wood_Oak_Trunk` — стволы как несущие стены |
| Пол/платформа | `Wood_Greenwood_Planks_Half` |
| Органические стены | `Rock_Calcite_Cobble` (мягкий, светлый камень) |
| Крыша | `Plant_Leaves_Birch` + `Wood_Birch_Branch_Long` — крона IS крыша |
| Корни (основание) | `Wood_Birch_Roots`, `Wood_Gnarled_Roots` |
| Мебель | `Furniture_Kweebec_*` |
| Свет | `Furniture_Kweebec_Lantern`, `Furniture_Kweebec_Lantern_Ceiling` |

**Техника строительства:**
1. Ствол дерева — центр и несущая конструкция (НЕ заменять!)
2. Строим вокруг ствола, а не вместо него
3. `Wood_Birch_Roots` у основания — ствол "вырастает" из земли
4. Платформы вешаются на ствол (`Wood_Greenwood_Planks_Half`)
5. Стены неполные, органичные — не сплошные прямоугольники
6. Крыша = продолжение кроны — ветки и листва сверху
7. Подземные комнаты: вход в корнях, комнаты уходят горизонтально вниз

**Отличие домов:**
- Разные виды деревьев (Birch, Oak, Beech)
- Некоторые — полностью подземные (вход в корнях)
- Разные уровни платформ: наземный / в кроне

**Запрещено**: Квадратные фундаменты. Прямые стены. Каменный кирпич.

---

### 2.3 Trork — Грубый / Брутальный / Укреплённый стиль

**Прообраз**: Средневековые форты и варварские лагери. Строят для защиты, не для красоты.

**Характер**: Тяжёлый, грубый, массивный. Никаких украшений. Сырой и слегка небрежный.

**Палитра блоков:**
| Роль | Блок |
|---|---|
| Основные стены | `Rock_Shale_Cobble` (тёмно-серый, угловатый) |
| Угловые усиления | `Rock_Stone_Cobble` (чуть светлее — контраст) |
| Дерево | `Wood_Deadwood_Beam` или `Wood_Drywood_Beam` — выветренное |
| Крыша | `Cloth_Roof_Hide_Flat` (шкуры) или плоская каменная |
| Частокол | `Wood_Drywood_Fence` |
| Акценты | `Deco_Bone_Skulls_Wall`, `Deco_Rope`, `Deco_Iron_Chains` |
| Свет | `Deco_Fire`, `Furniture_Crude_Brazier` |
| Мебель | `Furniture_Crude_*` |

**Техника строительства:**
1. Толстые стены (2 блока) у крупных строений — Trork'и строят с запасом
2. Низкие потолки (3 блока высота интерьера)
3. Никаких окон на уровне земли — только бойницы (1 блок шир., 2 блока выс.)
4. Частокол из `Wood_Drywood_Fence` вокруг лагеря
5. Сторожевые башни по углам: квадратные, 6–8 блоков высотой
6. В центре лагеря — костёр/жаровня с грубыми сиденьями вокруг
7. Здания в лагере не выровнены — слегка под углом, плотно, хаотично

**Уровни Trork лагеря:**
- Уровень 1: костёр + 1–2 грубых навеса
- Уровень 2: частокол + казармы (длинный прямоугольник)
- Уровень 3: каменные стены + башни

---

### 2.4 Нейтральный стиль (здания эльфа — общие)

Эльф строил везде, учился у всех рас. Его постройки функциональны, аккуратны, без излишеств.

**Характер**: Чистый, практичный, немного академический. Узнаётся как "не расовый".

**Палитра блоков:**
| Роль | Блок |
|---|---|
| Стены | `Rock_Stone_Brick` (обработанный камень) |
| Каркас | `Wood_Hardwood_Beam` (средне-коричневый) |
| Крыша | `Wood_Hardwood_Roof_Shallow` (пологая, функциональная) |
| Пилоны у входа | `Rock_Stone_Brick_Pillar_Base` + `Rock_Stone_Brick_Pillar_Middle` |
| Детали | `Rock_Chalk_Brick` — вставки для контраста |

## 3. Как Claude генерирует здания — Prefab Pipeline

### Формат префаба (верифицирован по sample.prefab.json, sample3-5)

Референсные префабы: [sample.prefab.json](convergence/devserver/prefabs/sample.prefab.json) · [sample3](convergence/devserver/prefabs/sample3.prefab.json) · [sample4](convergence/devserver/prefabs/sample4.prefab.json) · [sample5](convergence/devserver/prefabs/sample5.prefab.json)

Hytale хранит здания как `.prefab.json` файлы. Формат:
```json
{
  "version": 8,
  "blockIdVersion": 11,
  "anchorX": 0, "anchorY": 0, "anchorZ": 0,
  "blocks": [
    {"x": 0, "y": 0, "z": 0, "name": "Rock_Chalk_Brick"},
    {"x": 0, "y": 1, "z": 0, "name": "Furniture_Village_Door", "rotation": 2},
    {"x": 0, "y": 2, "z": 0, "name": "Furniture_Village_Door", "rotation": 2, "filler": 1024}
  ],
  "fluids": [
    {"x": 0, "y": 0, "z": 0, "name": "Empty", "level": 0},
    ...
  ]
}
```
- `anchorX/Y/Z` = всегда 0 (якорь в начале координат)
- `blocks[]` = только ненулевые блоки, **строчные ключи** (`x`, `y`, `z`, `name`)
- `fluids[]` = `Empty` запись для каждой позиции где есть блок (обязательно, включая filler-позиции)
- Координаты относительны якорю: `z < 0` = South (фасад/дверь), `z > 0` = North (тыл)
- **Важно**: генерировать через Python-скрипт, не через LLM напрямую — заглавные ключи (`X`, `Y`, `BlockName`) не работают

### Мультиблоки (двойные блоки)

Некоторые блоки занимают 2 вокселя по высоте. Нижний — основной, верхний — `filler`:
```json
{"x": 0, "y": 1, "z": -4, "name": "Furniture_Village_Door", "rotation": 2},
{"x": 0, "y": 2, "z": -4, "name": "Furniture_Village_Door", "rotation": 2, "filler": 1024}
```
Мультиблоки (верифицировано): `Furniture_Village_Door`, `Roof_Steep`, `Roof_Steep_Corner_*`

### Крышные блоки (верифицировано sample3-5)

| Блок | Описание | Filler |
|---|---|---|
| `*_Roof_Flat` | Плоская плитка | нет |
| `*_Roof_Shallow` | Пологий скат | `filler: 31` |
| `*_Roof_Steep` | Крутой скат, 2 вокселя высотой | `filler: 1024` |
| `*_Roof_Steep_State_Definitions_Corner_Left` | Угол крыши левый | `filler: 1024` |
| `*_Roof_Steep_State_Definitions_Corner_Right` | Угол крыши правый | `filler: 1024` |

**Rotation для Roof_Steep** (скат падает в сторону rotation):
- `rotation=0` → скат на South (z уменьшается)  ← [верифицировано sample5]
- `rotation=1` → скат на East (x увеличивается)
- `rotation=2` → скат на North (z увеличивается)
- `rotation=3` → скат на West (x уменьшается)

**Дверь**: `Furniture_Village_Door`, `rotation=2` → дверь лицом на South (игрок подходит с South). [sample5](convergence/devserver/prefabs/sample5.prefab.json)

### Якорный блок (Founding Stone) в префабе

Два сценария:

**Сценарий А — префаб сохранён командой `/prefab save` из игры:**
Founding Stone будет в `blocks[]` на (0,0,0) с `components` и `filler` полями (как в sample.prefab.json).
При чтении через `PrefabStore.forEachBlock()` нужно **пропускать** этот блок — он уже стоит.

**Сценарий Б — префаб генерируется программно (Claude/BuildingGenerator):**
Founding Stone в `blocks[]` **не включается** — игрок уже поставил его, строится только здание вокруг.
Именно так работают наши сгенерированные файлы (`town_hall_level1.prefab.json` и т.д.).

### Как использовать в игре

**Быстрая проверка (без кода):**
1. Скопировать файл в `devserver/prefabs/<name>.prefab.json`
2. В игре: paste brush → `e` → выбрать из "server" списка

**В коде мода:**
```java
// Через PrefabStore (если файл в ресурсах мода):
BlockSelection sel = PrefabStore.getServerPrefab("town_hall_level1");
sel.forEachBlock((x, y, z, block) -> {
    // пропустить якорный блок если он есть:
    // if (x == 0 && y == 0 && z == 0) return;
    world.setBlock(anchorX + x, anchorY + y, anchorZ + z, blockName);
});

// Или: конвертировать JSON → List<BlockEntry> → ResourceBlockPlacer
// (не требует PrefabStore, работает через наш существующий пайплайн)
```

### Флоу для стороннего билдера

1. Билдер заходит на dev-сервер → `/editprefab new building_name`
2. Ставит Founding Stone как якорь, строит здание вокруг
3. Выделяет area → `/prefab save`
4. Присылает `devserver/prefabs/building_name.prefab.json`
5. Я читаю файл, при необходимости конвертирую в наш формат (убираю `filler` блоки, пропускаю якорь)

## 4. Планировка деревни

### Принципы

- **Дороги**: никогда идеально прямые. Пусть слегка изгибаются. Главная — 3–4 блока шириной, переулки — 1–2 блока.
- **Здания лицом к дороге** — двери смотрят на улицу.
- **Центральная площадь** — Town Hall или колодец, к нему ведут все дороги.
- **Разная высота** — не выравнивать рельеф. Здание на 2–3 блока выше соседнего = интереснее.
- **Зонирование**: мастерские вместе, жилые дома вместе, центральная площадь для общих зданий.
- **Расстояние между домами**: 2–4 блока — переулки, огородики, поленницы.

### Рекомендуемый порядок застройки

1. Founding Stone → Town Hall (центр деревни)
2. Склад (рядом с Town Hall)
3. Первые жилые дома вокруг Town Hall (не симметрично!)
4. Дороги/тропинки — после определения мест домов
5. Рабочие здания (лесопилка, ферма) — ближе к ресурсам, ближе к краю деревни
6. Расширение: кварталы Kweebec и Trork с их стилем
