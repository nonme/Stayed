# Stayed — план разработки мода для Hytale

> **Концепция:** Игрок встречает эльфа-мудреца и вместе основывает поселение. Через спасения и истории к деревне присоединяются жители. Деревня растёт, даёт реальную пользу: автоматизированная добыча ресурсов, еда, защита.
>
> **Главная ценность:** ощущение присутствия — живая деревня рядом. Не инструмент производства, а компания. Механики существуют чтобы поддерживать это ощущение.
>
> **Текущий фокус:** жители-люди. Другие расы Orbis (Kweebec, Trork, Feran) — на потом, под вопросом.

**Стек:** Java 25 + Hytale Modding API, IntelliJ IDEA / VS Code, Gradle (Kotlin DSL)

---

## Ключевой NPC — Эльф-мудрец

Старый эльф-архитектор/учёный. В молодости путешествовал по Orbis, изучал культуры и архитектуру всех рас. Физически немощен — не может далеко ходить, сражаться, добывать ресурсы. Но владеет знаниями о строительстве и культурах.

**Роль в игре:**
- **Строитель общих зданий** — эльф строит Town Hall, склад, рабочие здания.
- **Советник/квестодатель** — через диалог направляет игрока к новым расам и подсказывает следующие шаги.
- **НЕ мэр** — лидер деревни = игрок. Эльф — помощник.
- **Бессмертен** — игровой условный приём: эльф не может погибнуть в бою, чтобы не сломать прогрессию.

**Как работает:**
- Игрок находит эльфа в палатке рядом со спавном (гарантированно близко).
- Эльф сидит у костра, speech bubble: *"Путешественник? Давно я не видел разумных существ..."*
- F по эльфу → диалог (InteractiveCustomUIPage).
- Игрок ставит Founding Stone → эльф переезжает, начинает строить Town Hall.
- Эльф живёт в Town Hall после постройки.

**Взаимодействие с NPC:**
- **F-key** по NPC → UI диалога/управления (Role JSON interaction → UseEntity → Java handler → openCustomPage).
- **Speech bubbles** — NPC периодически говорят фразы над головой (invisible entity + Nameplate). Фразы зависят от состояния (работа, отдых, голод, счастье).
- Все диалоги и UI — нативные (InteractiveCustomUIPage + .ui файлы), 0 зависимостей.

## Жители

| NPC | Роль | Статус |
|---|---|---|
| **Эльф-мудрец** | Уникальный NPC, советник, бессмертный, один на деревню | Реализовано |
| **Жители (Humans)** | Разные профессии в зависимости от backstory. Quest recruitment, рандомный скин/имя | Реализовано |

Другие расы Orbis (Kweebec, Trork, Feran, эльфы-учёные) — на потом, под вопросом. Сейчас все жители — Humans.

### Откуда берутся жители

Жители **не появляются из воздуха** — каждый новый житель это сюжетная единица.

**Канал 1: Quest recruitment (основной)** — игрок спасает беженцев через encounter'ы разных типов. Жители рандомные: имя, внешность, backstory из пула. Квесты доступны параллельно с постройкой зданий.

**Канал 2: Дети** — пара в доме уровня 2+ со временем заводит ребёнка. Ребёнок вырастает → если есть свободный дом — заселяется. Взрослый ребёнок ищет пару только среди жителей с другим `familyId`. Требует API поддержки scale для NPC-модели.

**Канал 3: Market recruitment (поздняя стадия)** — деревня известна → путники приходят к рынку → можно предложить остаться. См. раздел "Рынок и экономика".

### Квесты спасения

**Общий flow:**
1. Игрок идёт к точке (300-500 блоков от деревни), выполняет механику спасения.
2. F на спасённом → диалог → NPC следует за игроком в деревню.
3. Приход в деревню → конверсия в жителя, селится в Town Hall пока нет другого жилья.
4. Новые квесты доступны параллельно с постройкой зданий.

**Тон:** серьёзный. Все спасённые — беженцы, потерявшие дом. Мир Orbis суров (The Shattering). Это объясняет почему они остаются: им некуда идти.

**Жители рандомные:** имя, внешность (PlayerSkin), backstory генерируются из пула при спавне. Привязанность формируется не через заскриптованную историю а через наблюдение за живым NPC с поведением и потребностями.

#### Реализованные типы

**Ловушка-яма** — prefab ямы 3×3×4 из камня. Снаружи обвалившиеся брёвна и земляные блоки. На поверхности патрулируют 1-2 гоблина. Убить гоблинов → разбить завал → F на NPC → выбирается наверх → следует.

**Клетка разбойников** — мини-лагерь (костёр + 2-3 хижины) + клетка из брёвен. 2 охранника (Outlander / Outlander_Brute). Убить охрану → разрушить блок клетки → F → следует.

**Спасение с высоты** — NPC застрял на верхушке дерева/скалы. Внизу хищники (волки/медведи). Убить хищников — NPC спускается сам.

**Забаррикадированный выживший** — полуразрушенная хижина, проём заколочен досками. Снаружи 2-3 враждебных моба. Убить мобов → сломать блоки → F → следует.

#### Планируемые типы

**Вынужденная приманка** — NPC стоит у дороги, нормально выглядит, просит помощи. F → крик *"Прости меня, они заставили!"* → засада гоблинов. Моральная дилемма в UI: взять / отказать. Оба варианта рабочие.

**Откуп или кровь** — врата лагеря разбойников. Громила держит NPC. UI: заплатить ресурсы (мирно) или атаковать (бой). Оба пути ведут к спасению.

**Завалило в пещере** — NPC зажат завалом. Темно. Диалог: разгрести завал + дать факел из инвентаря. Два шага — физический и психологический.

#### Лор эльфа

Эльф даёт квесты как будто знает заранее, где кто-то в беде. Намеренная загадка. Возможные раскрытия: древний провидец / связан с духами Orbis / остатки магической сети.

### Система семей и роста населения

**Семья** — пара жителей с флагом `familyId`. Живут в одном доме.

**Дети:**
- Условие: дом уровня 2+, пара есть, детей в доме нет, в деревне достаточно еды
- Через время появляется ребёнок (уменьшенная модель)
- Ребёнок вырастает → если есть свободный дом — переселяется
- Взрослый ребёнок ищет пару только среди жителей с другим `familyId`
- Если пары нет — остаётся холостым (сигнал строить Market)

**Уровни дома (residential):**
- Уровень 1: 2 жителя (пара). Только материалы Zone 1 (стартовая зона Orbis — softwood, базовый камень, мягкие ткани).
- Уровень 2: 3 жителя (пара + ребёнок). Добавляются материалы Zone 2 (darkwood, твёрдый камень, более качественные ткани, металлические детали).
- Уровень 3: 4 жителя (пара + 2 детей). Добавляются материалы Zone 3/4 (редкие породы дерева, экзотические камни, декоративные элементы).
- Апгрейд = эльф достраивает здание (расширение prefab'а), требует ресурсы.
- Архитектурный стиль дома сохраняется при апгрейде — добавляются только материалы более высокой зоны, форма наращивается органично.

**Диагностика в UI ратуши** — всегда показывает одно узкое место роста:
- "Нет свободных домов" → строй дом
- "Нет пар без родства" → строй Market
- "Мало еды" → строй ферму

## Категории зданий

На доске целей и в Build Menu здания группируются по **функциональным категориям** — что здание делает, не как оно организовано внутри. Игрок видит "I need food" → смотрит в Production. "I need to make tools" → Crafting.

### Функциональные категории (для UI)

| Иконка | Название | Что значит | Здания |
|---|---|---|---|
| 🪓 | **Production** | Извлечение сырья из природы | Woodcutter's Hut, Farm, Mine, Fisher's Hut, Hunter's Hut |
| 🔨 | **Crafting** | Переработка сырья в товары | Sawmill, Forge, Mill, Bakery, Brewery |
| 🍺 | **Services** | Услуги жителям | Tavern, School, Shrine, Market |
| 🛏️ | **Housing** | Жильё для жителей | House, Porter's Lodge, Barracks |
| ⚔️ | **Defense** | Защита деревни | Guard House, Watchtower |
| 📦 | **Storage** | Хранение ресурсов | Warehouse |
| 🏛️ | **Civic** | Управление деревней | Town Hall |

### Жилищные значки (badges на здании)

Параллельно с категорией каждое здание имеет **значок** показывающий его связь с жильём. Игрок видит сразу, нужен ли работнику дом или здание само-содержащееся:

| Значок | Смысл | Tooltip |
|---|---|---|
| 🏠 | Self-housed | "Worker lives in this building" |
| 🛠️ | Work-only | "Requires a Dwelling for the worker" |
| 🛌×N | Residential | "Houses N residents (any role)" |
| 🛌×N + role icon | Worker housing | "Houses N workers of specific role (e.g. porters, guards)" |

Категория + значок дают полную картину одним взглядом: *"Sawmill — это 🔨 Crafting, 🛠️ нужен дом для плотника"*. *"Porter's Lodge — это 🛏️ Housing, 🛌×3 для носильщиков"*.

### Правило для дизайнера (внутренняя классификация)

Решая нужно ли новому зданию само-жильё, ответ один:

> **Работник работает с природой/местностью → 🏠 self-housed.**
> **Работник работает с предметами/людьми → 🛠️ нужен дом.**

Это правило снимает вопрос "где он живёт" для любого нового здания. Применение:

- **Production** (Woodcutter, Farm, Mine, Fisher, Hunter) — работают с природой → 🏠 self-housed. Хижина на периферии, у ресурса.
- **Crafting** (Sawmill, Forge, Mill, Bakery) — работают с сырьём → 🛠️ нужен дом. Стоят в центре деревни.
- **Services** (Tavern, School, Market, Shrine) — работают с людьми → 🛠️ нужен дом. Стоят в центре деревни.
- **Defense** (Guard House) — несёт службу круглосуточно → 🏠 self-housed (или 🛌×N для Казармы).
- **Storage** (Warehouse) — без постоянного работника → 🛠️.
- **Housing** — категория для зданий которые **дают** жильё другим.

## Прогрессия

Прогрессия не линейная. Игрок видит **доску целей** (планшет в Town Hall), выбирает что строить в каком порядке. Здания не блокируют друг друга — они дают **бусты и решают конкретные проблемы**.

Два явных этапа (основание и оборона) дают игроку структуру в начале игры. Остальные здания доступны параллельно, когда игрок захочет.

### Этап 1 — Основание (что есть сейчас + порядок)

**Цель:** базовая экономика и самообеспечение.

**Состав:**
1. **Town Hall** (Founding Stone) — центр деревни. Эльф живёт здесь. 3 койки для безработных. UI: имена жителей, ресурсы, доска целей.
2. **Хижина лесоруба** — лесоруб живёт и работает здесь. Пока нет склада, носит брёвна в сундук Town Hall (ограниченная вместимость).
3. **Хижина фермера** — фермер живёт и работает здесь. Овощи/зерно в Town Hall.
4. **Шахта** (одним префабом с хижиной шахтёра) — добыча камня, угля, руды. Хижина шахтёра встроена в префаб.
5. **Склад (Warehouse)** — большое хранилище. Сам по себе ничего не делает.
6. **Дом носильщиков** — 3 носильщика. Они автоматически переносят ресурсы от рабочих зданий к складу, и обратно (сырьё → перерабатывающее здание). Без хижины носильщиков ресурсы носят сами работники, отрываясь от работы.

**Что происходит с ресурсами из Town Hall при постройке склада:** ресурсы **остаются** в сундуке Town Hall. Это исторический склад "первых дней". Новые ресурсы носильщики несут в Warehouse. Town Hall становится резервным сундуком.

**Жителей к концу этапа:** 5-7 (3 добытчика + 1-3 носильщика + безработные в Town Hall).

**Эмоциональный финал этапа:** разведчик-гоблин появляется на холме. Не атакует. Эльф: *"Они нас увидели. Скоро будет беда."*

### Этап 2 — Оборона

**Цель:** отбить нападение гоблинов.

**Триггер нападения:** через несколько игровых дней после появления разведчика.

**Первое нападение (лёгкое):**
- 2-3 гоблина приходят пешком из-за границы карты.
- Жители **invulnerable** — никого не убьют.
- Жители прячутся в Town Hall — деревня **встаёт** (никто не работает) пока гоблины бродят.
- Игрок убивает гоблинов сам. Это **возможно** без подготовки — пара гоблинов отбивается мечом.
- Элф комментирует: *"Они вернутся большим числом. Готовься."*

**Состав этапа:**
1. **Guard House (lvl1)** — 1 стражник, патрулирует периметр. Self-housed.
2. **Кузница (Forge)** — производит мечи, копья, броню из руды. Без неё стражники безоружны. Кузнец живёт в Town Hall (тут начинается необходимость в доме — но дом строится в этапе 3).
3. **Хижина рыбака** или **охотника** — альтернативный источник еды на случай если ферма пострадает.

**Большое нападение (после нескольких рейдов):**
- 5-8 гоблинов приходят волной.
- Стражники + игрок отбивают.
- Без подготовки (кузницы, нескольких стражников) — деревня дольше стоит, накапливаются жалобы жителей. Конкретные последствия (повреждения, потери ресурсов) — пока не решено.

**Эскалация:**
- 1-й рейд: 1 разведчик → бросает разведку, не нападает
- 2-й рейд: 2-3 гоблина → лёгкое нападение, деревня встаёт
- 3-й рейд: 4-5 гоблинов → нужны стражники
- 4-й и далее: 5-10 гоблинов → нужна Казарма (Guard House lvl3)

**Guard House → Казарма:** один тип здания с тремя уровнями.
- lvl1 Guard House: 1 солдат (self-housed)
- lvl2: 2 солдата
- lvl3 Казарма: 4-5 солдат (worker housing)

### Опциональные здания (можно строить когда угодно)

**Это не отдельный этап.** Эти здания доступны параллельно с этапом 1, как только игрок захочет. Они дают **бусты и качество жизни**, не разблокировки. Игрок не обязан их строить, но с ними эффективнее.

Жители показывают на доске целей **жалобы**: что им не нравится, на что они жалуются. Игрок сам решает, какую жалобу закрывать первой и хочет ли вообще.

**Sawmill (лесопилка)** — повышает выход досок из брёвен.
- Без Sawmill: 1 бревно → 1 блок досок (нативный Hytale recipe)
- С Sawmill: 2 бревна → 3 блока досок (бонус ~50%)
- Плотник работает в Sawmill, живёт в **доме**.

**Дом (Residence)** — нужен когда появляются работники work-only зданий (плотник, повар, кузнец).

**Таверна** — повар готовит еду из ингредиентов.
- Без таверны жители едят сырые овощи → насыщает мало, жалуются.
- С таверной — приготовленная еда эффективнее, рецепты дают разнообразие.

**Хижина рыбака / охотника** — альтернативные источники еды. Закрывают жалобу "одна и та же еда".

**Мельница + Пекарня** — цепочка зерно → мука → хлеб.

**Пивоварня** — пиво. Может быть товаром на продажу или happiness-бустом (по контексту лора, не решено).

### Общественные институты (поздняя стадия)

Здания которые **не производят товар**, а оказывают услуги. Появляются когда деревня самодостаточна:

**Школа** — учит детей. Без школы дети тоже растут, но школа даёт буст к будущим профессиям.

**Храм / Святилище** — happiness через ритуалы, похороны, праздники.

**Рынок (Market)** — торговля + рекрутинг путников. См. отдельный раздел.

**Университет / Библиотека** — research, новые рецепты.

## Доска целей (Planner Board)

Чтобы избежать линейности «эльф диктует следующий квест», игрок использует **доску целей** в Town Hall UI.

**Главное содержимое доски — жалобы жителей.** Это естественная навигация по тому что строить дальше: жители сами говорят чего им не хватает.

**Дополнительно:**
- **Список доступных зданий** с категориями (Hearthside / Workshop / Dwelling / Quarters) и кратким описанием эффекта.
- **Слухи (rumours)** — раз в N дней через торговца/путника/ворона приходит фрагмент новостей: *"Говорят, в соседней деревне открыли таверну и народ к ним стекается"*. Не приказ, а идея.

Это создаёт ощущение что **деревня сама** диктует развитие, а не игра.

## Стражники как компаньоны (поздняя фича)

Игрок может **взять** стражника с собой как спутника в путешествие.
- Стражник идёт за игроком, защищает в бою
- Когда игрок возвращается в деревню — стражник возвращается на пост
- Один компаньон за раз
- Стражник теряет productivity для деревни пока в путешествии (стоит на посту, но не патрулирует)

Это превращает деревню не только в место производства, но и в **базу для приключений**. Адаптируется из existing follow-механики rescue-квестов (`Villager_Rescue_Follower.json`).

## Поведение жителей на работе (job-loop)

Каждый работающий житель живёт по суточному циклу. Цикл тикает по серверному времени.

**Общий распорядок (для жителей которые живут не на работе):**
- **Утро:** житель выходит из дома → идёт к рабочему зданию
- **День:** работает (анимация + производство ресурсов по таймеру)
- **Обед:** короткая пауза, идёт в таверну (если есть) или ест на месте
- **Вечер:** возвращается домой
- **Ночь:** стоит/сидит у дома (idle анимация)

**Для self-housed работников (лесоруб, фермер, шахтёр и т.д.):**
- В деревню физически **не ходят** — живут на работе
- Носильщики из Дома носильщиков забирают у них ресурсы
- На праздники (см. ниже) приходят в центр деревни

**Лесоруб (пример self-housed):**
- Работает у хижины — рубит деревья в радиусе ~20 блоков
- Складывает брёвна в сундук хижины
- Носильщик приходит → забирает → несёт в склад
- Если носильщика нет — сам несёт в Town Hall/склад (медленнее)

**Счастье и продуктивность:**
- Счастье обновляется раз в игровой день
- Продуктивность = множитель на количество производимых ресурсов за цикл
- Безработный житель не несчастен, но со работой счастливее

## Назначение работников

**По умолчанию: автоматическое.** При постройке здания первый подходящий безработный из Town Hall автоматически назначается работником.

**Условия для авто-назначения:**
- Self-housed здание: есть койка → переезжает работник
- Work-only здание: нужен дом → если есть свободная койка в доме → назначается; если нет — здание стоит пустым с маркером "нужен дом"
- Worker housing (Дом носильщиков, Казарма): принимает только соответствующую роль

**Override:** игрок может через UI здания переназначить вручную (уволить текущего, выбрать другого из списка).

Это снимает Minecolonies-боль (постоянно открывать UI каждого здания), но даёт контроль когда нужно.

## Жизнь деревни — как сделать её живой

Главная ценность мода — **ощущение присутствия**. Несколько систем работают вместе:

### Слой 1: Абстрактная экономика (не симуляция)

Еда считается **на уровне деревни**, не на уровне жителя. Каждый житель потребляет N еды в сутки. Если общая еда упала ниже порога → happiness падает у всех. Это снимает баг "лесоруб идёт через всю карту за едой".

Носильщики физически переносят ресурсы — но это **визуальная анимация**, не bottleneck. Если носильщик не дошёл — экономика всё равно работает.

### Слой 2: Видимые носильщики

1-3 NPC из Дома носильщиков постоянно курсируют между рабочими зданиями и складом. Несут корзины, мешки. Это **главный источник движения** на дорогах деревни. Каждый — полноценный NPC со скином, именем, расой.

### Слой 3: Распорядок дня

Утром жители выходят из домов на работу. Вечером возвращаются. Ночью — огни в окнах. Self-housed работники в центре деревни не ходят (они на периферии), но городские (плотник, повар, кузнец) активно перемещаются между домом и работой.

### Слой 4: Праздники и события

- **Праздник урожая** (раз в N дней при работающей ферме) — все жители (включая периферийных лесорубов и шахтёров) собираются в центре. +happiness на 1 день.
- **Свадьба** (когда два жителя из разных семей образуют пару) — аналогично, общий сбор.
- **Прибытие торговца** (раз в N дней при наличии Market) — торговец идёт по дороге к Market, остаётся на день, можно купить редкое.
- **Похороны** (когда житель умирает от старости) — траурное собрание, элф ведёт обряд.
- **Визит элфа к жителю** — элф приходит к конкретному жителю с советом/квестом.

Праздники — главный инструмент оживления. Это **единственное время** когда лесоруб появляется в деревне. Игрок запоминает события → деревня кажется живой.

### Слой 5: Микро-жизнь

- Жители говорят 5 секунд при встрече (speech bubbles — инфраструктура есть)
- Дети бегают вокруг домов (когда появятся)
- Дым из труб мастерских когда работают
- Огонь в окнах ночью

## Система счастья и жалоб

Каждый житель имеет **счастье (0–100%)** → влияет на **продуктивность**.

Вместо одного "числа happiness" для игрока — на доске целей в Town Hall показываются **жалобы жителей**. Каждая жалоба ссылается на конкретного жителя и говорит, что ему не нравится. Это даёт игроку понятную информацию что делать, а не абстрактный модификатор.

**Примеры жалоб** (точные формулировки и эффекты — по мере реализации):
- *"Ярика жалуется: всё время едим одно и то же"* → построить рыбака/охотника, разнообразить еду
- *"Бьорн ест сырые овощи"* → построить таверну
- *"Анна спит в Town Hall, у неё нет своего дома"* → построить House
- *"Ингрид боится гоблинов"* → построить Guard House / Казарму
- *"Йорик скучает: некуда сходить вечером"* → построить таверну/храм

Жалобы — это **сигнал**, не **жёсткое требование**. Игрок может игнорировать, но накопление жалоб снижает productivity и может приводить к уходу жителей (поздняя механика).

Конкретные модификаторы счастья (числа) определятся при реализации. Базовый принцип: позитивные факторы (дом, работа, разнообразная еда, безопасность, праздники) повышают счастье; их отсутствие — снижает.

## Система якорных блоков

Каждое здание привязано к **якорному блоку** — тематическому предмету, который определяет тип здания. Якорный блок остаётся внутри здания после постройки как функциональный элемент.

**Текущие якоря (кастомные блоки Stayed_*):**

| Здание | Якорь |
|---|---|
| Town Hall | Stayed_Founding_Stone |
| House | Stayed_House (Brazier-style) |
| Warehouse | Stayed_Warehouse |
| Хижина лесоруба | Stayed_Woodcutters_Hut |
| Sawmill | Stayed_Sawmill |
| Шахта | Stayed_Mine |
| Guard House | Stayed_Guard_House |
| Кузница | Stayed_Forge |
| Таверна | Stayed_Tavern |
| Ферма | Stayed_Farm (Scarecrow) |

**Процесс строительства:**
1. Игрок ставит якорный блок в мире.
2. Появляется призрачное превью здания (Filter_Air_Block).
3. F по якорю → UI: Build / Rotate / Cancel.
4. Если "Build" — эльф приходит и строит блок-за-блоком.
5. После постройки якорь остаётся как интерактивный элемент.

Эльф — единственный строитель. Одна стройка за раз.

## Защита деревни — детали

### Триггер угрозы

После того как в деревне 3+ жителя — элф предупреждает: *"Слухи о нас расходятся. Гоблины могут прийти."*

4-й житель → разведчик-гоблин появляется на холме, не атакует, бродит несколько игровых дней, потом уходит.

5-й житель → первое нападение (2-3 гоблина).

### Особенности боя

- **Жители invulnerable** — гоблины не могут убить жителя. Жители прячутся в Town Hall.
- **Деревня встаёт** — пока гоблины бродят, никто не работает. Это игровое давление.
- **Здания могут пострадать** — гоблины ломают забор, разбивают окна. Восстановление требует ресурсов.
- **Стражники могут "пасть в обморок"** (не умереть) — после боя возвращаются в Guard House на восстановление.

### Эскалация рейдов

- Рейд 1: 1 разведчик (не атакует)
- Рейд 2: 2-3 гоблина (лёгкий)
- Рейд 3: 4-5 гоблинов (нужны стражники)
- Рейд 4+: 5-10 гоблинов (нужна Казарма + кузница для оружия)

Рейды **продолжаются и дальше** — это не разовая фаза, а постоянный фон. Как развивать эту угрозу нарративно (новые типы врагов, осада, перемирие, союз) — посмотрим по мере развития истории.

### Большое нападение

Перед волной — **сигнал**: разведчик-гоблин появляется и **убегает** (скриптом). Элф: *"Он нёс информацию. Жди беды."*

Видимый таймер в UI ратуши: дни до нападения. На горизонте видны костры гоблинов (визуальный сигнал).

После большого нападения — несколько игровых дней спокойствия, потом новый цикл.

## Рынок и экономика (поздняя стадия)

### Идея

Рынок — **второй канал рекрутинга** и упрощение для игрока: не нужно крафтить всё, можно покупать за золото от продажи ресурсов.

**Story-wise:** деревня известна → к рынку приходят купцы-путники → среди них находятся те, кто хочет остаться. Эльф: *"Путники приходят на рынки. Если наша деревня прославится — сюда потянутся те, кто ищет новый дом."*

### Золото

- Хранится в **казне Town Hall** (счётчик, не физический item).
- Показывается во вкладке "Казна" в TownHallPage.
- Все транзакции (продажа, покупка, вербовка) списывают/добавляют из казны.

### Market — здание

- **Якорь:** прилавок (Stayed_Counter — уже есть).
- **Категория:** work-only (торговец живёт в доме).
- Эльф строит как любое здание.
- 2-3 прилавка внутри, вывеска.

### Market UI

Три вкладки:

**1. Продать** — список товаров из склада, цена. Продаёшь → золото в казну.

**2. Купить** — список доступных товаров (ограниченный, "сегодня привезли"). Золото → склад.

**3. Путники** — visitor'ы сейчас на рынке. Раса/профиль/цена вербовки. Кнопка *"Предложить остаться"*.

### Visitor'ы

- В торговый день приходят 1-3 visitor'а. Спавн за границей loaded-area, идут пешком к Market.
- Профили: *"лесоруб с севера"*, *"странник с гор"*, *"ремесленник"*. Разные профили покупают/продают разное.
- **Рекрутинг:** есть свободный дом + золото на подъёмные (10-50g) + happiness деревни > порог → F на visitor'е → диалог *"Не хочешь остаться?"* → конверсия в жителя.

### Торговый день

Market работает **не постоянно**:
- Таймер: раз в N игровых дней открывается на M минут, **или**
- Активация игроком: кнопка *"Открыть рынок"*, тратит еду/золото на рекламу.

Создаёт ритм: копишь ресурсы → открываешь день → торгуешь и вербуешь → рынок закрывается.

### Цены

Fixed prices с возможностью дневных колебаний ±30% для разнообразия.

## Backward compatibility

Все изменения в данных должны быть **drop-in replacement**. См. CLAUDE.md раздел "Backward compatibility" для деталей.

**Что нельзя:**
- Переименовывать BuildingType string-константы (`WOODCUTTERS_HUT`, `SAWMILL`, и т.д.) — старые сейвы их хранят.
- Переименовывать BSON-ключи компонентов или сами компоненты.
- Менять типы существующих полей в кодеках.
- Переименовывать role-файлы NPC, prefab-файлы, objective ID.

**Что можно:**
- Добавлять новые поля в кодеки (с дефолтами).
- Добавлять новые BuildingType с новыми константами.
- Добавлять новые prefab-файлы.

При добавлении категорий зданий — новые методы в `BuildingType` (например `getCategory(String type)`), не переименование существующих констант.
